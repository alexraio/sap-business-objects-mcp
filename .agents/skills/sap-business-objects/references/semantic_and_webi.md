# Semantic Layer & Web Intelligence Runbook

This reference provides detailed technical instructions and workflows for inspecting universes, extracting Data Provider SQL, handling prompts, and retrieving tabular report data using `bo-mcp`.

---

## 1. Semantic Layer & Universe Exploration

### 1.1 Universe Discovery & Metadata
* **List Universes:**
  Call `get_universes()` to retrieve all published Universes (UNX and UNV) with their `id`, `name`, and `folderId`.
* **Inspect Details:**
  Call `get_universe_details(universe_id)` to check:
  - Engine type: `unx` (relational or multi-source UNX) or `unv` (legacy Universe).
  - CUID and technical names.
* **Inspect Connection ID:**
  Call `get_universe_connection_id(universe_id)` to identify the underlying relational connection resource.
  > **Connection Testing Notice:** Remember that database connectivity for relational connections cannot be tested in the CMC. Test exclusively in **Information Design Tool (IDT)** for UNX or **Universe Design Tool (UDT)** for UNV.

### 1.2 Inspecting Business Classes & Objects
* Call `get_universe_structure(universe_id)`.
* Returns hierarchical classes, subclasses, dimensions, attributes, and measures.
* **Usage:** Use this to verify available business metrics, check naming conventions, and locate fields required for building or modifying report queries.

### 1.3 Universe Lineage & Impact Analysis
* Before modifying or retiring a universe, call `get_universe_related_reports(universe_id)`.
* Returns the complete list of Web Intelligence documents currently referencing this universe.
* Use this list to assess blast radius and plan migration or re-pointing tasks.

## 2. Web Intelligence Documents & Navigation

### 2.1 Locating Documents
* **Root / Global Listing:** Call `get_documents()` to get an overview of accessible documents.
* **Folder-Specific Listing:** Call `get_webi_docs(folder_id)` to locate reports stored in a specific corporate folder.
* **Document Inspection:**
  - Call `get_doc_details(document_id)` for general metadata (CUID, folder ID, updated time).
  - Call `get_doc_properties(document_id)` for operational flags (refresh on open, auto-save, formatting locale).

---

## 3. Data Providers, SQL Inspection & Repointing

### 3.1 Listing Data Providers & Extracting SQL
Each Web Intelligence report contains one or more Data Providers (queries):
1. **List Data Providers:**
   `get_dp(document_id)` returns `id`, `name`, `datasourceId`, and `datasourceType`.
2. **Extract Generated SQL:**
   `get_dp_sql(document_id, dp_id)` returns the exact native SQL query generated by the Semantic Layer engine for the target database.
3. **Inspect Query Specification:**
   `get_dp_specification(document_id, dp_id)` returns the query specification defining selected result objects, filters, and query properties.

### 3.2 Repointing Data Sources (Change Data Source)
When migrating a report from UNV to UNX or between universes:
1. Call `get_dp_mapping_proposal(document_id, dp_id, target_datasource_id)`.
   Review the automatic field mapping proposal generated by the engine.
2. If adjustments are needed, prepare a `mapping_spec` dictionary.
3. **Tier 2 Action:** Confirm with the user before executing:
   `change_dp_datasource(document_id, dp_id, target_datasource_id, mapping_spec)`.

### 3.3 Purging & Refreshing Individual Queries
* `refresh_dp(document_id, dp_id)`: Refreshes only the selected data provider.
* `purge_dp(document_id, dp_id)`: Purges cached query data (Tier 2 confirmation required).

## 4. Prompts, Parameters & Document Refresh

### 4.1 Resolving Prompts
Reports with dynamic prompts require answering parameters before refresh:
1. **Discover Parameters:**
   Call `get_doc_parameters(document_id)` to retrieve parameter names, IDs, prompt types, and whether they are optional or mandatory.
2. **Query List of Values (LOV):**
   Call `get_parameter_lov(document_id, parameter_id)` to retrieve valid selectable values.
3. **Execute Document Refresh:**
   Call `refresh_webi_doc(document_id, parameters)` where `parameters` is a structured dictionary:
   ```python
   {
       "ParameterNameOrID": ["SelectedValue1", "SelectedValue2"]
   }
   ```
   If no parameters are required, call `refresh_webi_doc(document_id)`.

## 5. Extracting Tabular Data & Report Blocks

To avoid context explosion, extract tabular data defensively:

```
[Document] ──> get_reports() ──> [Report Tabs]
                                       │
                                       ▼
                       get_report_elements() ──> [Blocks / Tables]
                                                       │
                                                       ▼
                                            get_report_element_data() ──> [Cell Matrix]
```

### 5.1 Step-by-Step Procedure
1. Call `get_reports(document_id)`:
   Returns report tabs (e.g., `id: "1"`, `name: "Executive Summary"`).
2. Call `get_report_elements(document_id, report_id)`:
   Inspects visual elements (tables, charts, forms) on that tab. Identify table elements by type (`Table`, `VTable`, `XTable`).
3. Call `get_report_element_data(document_id, report_id, element_id)`:
   Extracts header columns, row counts, and cell data.
4. Call `get_variables(document_id)` if you need formulas, calculated dimensions, or report-level variables.

## 6. Document Lifecycle Actions (Tier 2 Safeguards)

* **Save Document (`save_webi_doc`):**
  Saves the document, optionally as a new copy or to another folder:
  `save_webi_doc(document_id, folder_id=target_folder, name="New Name")`.
  *Confirmation rule:* Summarize whether this overwrites the existing report or creates a new copy.
* **Delete Document (`delete_webi_doc`):**
  Permanently deletes the document from the repository.
  *Confirmation rule:* Verify report name, ID, and parent folder with the user before calling `delete_webi_doc(document_id)`.

## 7. Exporting Documents & Reports (PDF, Excel, CSV)

Raylight REST Web Services allow exporting full Web Intelligence documents or individual report tabs using content negotiation via the HTTP `Accept` header.

### 7.1 Export Formats & Endpoints

| Format | Target Level | Endpoint URL | `Accept` Header |
| :--- | :--- | :--- | :--- |
| **PDF** (`.pdf`) | Full Document | `GET /raylight/v1/documents/{documentId}` | `application/pdf` |
| **PDF** (`.pdf`) | Report Tab | `GET /raylight/v1/documents/{documentId}/reports/{reportId}` | `application/pdf` |
| **Excel** (`.xlsx`) | Full Document | `GET /raylight/v1/documents/{documentId}` | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| **Excel** (`.xlsx`) | Report Tab | `GET /raylight/v1/documents/{documentId}/reports/{reportId}` | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| **CSV** (`.csv`) | Report Tab | `GET /raylight/v1/documents/{documentId}/reports/{reportId}` | `text/csv` |

> ⚠️ **Note on CSV:** Entire multi-tab documents cannot be exported to a single flat CSV file in Raylight. The tool `export_webi_doc` automatically resolves the first report tab ID if `report_id` is omitted.

### 7.2 Tool Usage (`export_webi_doc`)

* **Export PDF (with In-Session Refresh):**
  `export_webi_doc(document_id="23856", export_format="pdf", refresh=True)`
* **Export Excel:**
  `export_webi_doc(document_id="23856", export_format="xlsx", refresh=True)`
* **Export CSV:**
  `export_webi_doc(document_id="23856", export_format="csv", refresh=True)`
* **Export All Formats Simultaneously:**
  `export_webi_doc(document_id="23856", export_format="all", refresh=True)`
* **Custom Output Directory / File:**
  `export_webi_doc(document_id="23856", export_format="pdf", output_path="/path/to/output.pdf", refresh=True)`
  If `output_path` is omitted, files are saved in the `exports/` folder relative to the workspace.

### 7.3 In-Session Refresh Before Export (`refresh=True`)

In SAP BusinessObjects Web Intelligence, report execution results are stored in an **in-memory document session state** on the Webi Processing Server. If `export_webi_doc` is called without refreshing, Raylight returns the static, last-saved document state from the CMS file repository (which may contain purged data or dummy placeholders).

Setting `refresh=True` executes `refresh_webi_doc(document_id)` within the **exact same HTTP session** immediately before streaming the export payload. For `export_format="all"`, the refresh executes once at the start of the call, guaranteeing that PDF, Excel, and CSV are all generated from the identical refreshed dataset.
